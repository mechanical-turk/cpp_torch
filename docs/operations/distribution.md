# Distribution Operations

## State and cadence

- `docs/distribution-timeline.md` is the append-only release and distribution
  ledger. Read it before release, announcement, repost, or scheduling advice.
- `youtube-series/production/posting-cadence.md` owns the standing schedule.
  Update that document when the cadence changes instead of inventing a parallel
  schedule.
- Record meaningful events as soon as known: recording and edit milestones,
  publication, announcements, Reddit submissions, community actions, Shorts,
  and decision-relevant analytics checkpoints.
- Preserve the platform, episode, Eastern Time timestamp, direct URL, status,
  and next dependent action. Mark approximate or unknown values honestly.
- Keep planned actions separate from completed events. Reschedule or cancel
  stale plans explicitly.
- Do not clutter the ledger with internal tooling, OAuth work, asset creation,
  or routine document maintenance unless it creates a learner action or blocker.

## Cross-platform rules

- Coordinate spacing without claiming that timing caused a result.
- Maintain genuine personal posts on X separately from announcements. Keep them
  native, self-contained, link-free by default, and never manufacture filler.
- Treat substantive replies inside large, relevant X conversations as an active
  distribution channel. Add a useful idea, example, or artifact that stands on
  its own. Do not chase reach with generic reactions, forced promotion, or
  unrelated links. Measure reply impressions, engagement, profile visits, and
  link clicks separately from original posts.
- Every X and LinkedIn episode announcement names
  `Episode N of Deep Learning, All the Way Down` after establishing a reason to
  care. Never open with release administration.
- The main X or LinkedIn announcement gets exactly one previewable external URL:
  the YouTube episode. Put playlist and GitHub links in the X navigation reply
  or LinkedIn author comment.
- Every X episode package includes one concise playlist and GitHub navigation
  reply.
- Do not use the recurring sentence about the implementation remaining one
  C++23 standard-library file in X or LinkedIn announcements.

## Reddit

- Reddit is a core weekly distribution channel, not an announcement feed.
- Read `reddit-engagement-research-2026-08-29.md` and
  `reddit-distribution-strategy.md` before preparing a post.
- Check current community rules and recent submissions. Use a new angle and new
  copy for each community.
- Lead with a concrete milestone and useful implementation evidence. Put GitHub
  before YouTube and end with one specific question.
- Answer substantive comments and record 24-hour, 48-hour, 72-hour, and
  seven-day checkpoints.
- If there is no worthwhile contribution, record an explicit defer.

## YouTube Posts and Community

Read `youtube-community-growth-research-2026-08-29.md` before planning either.
Treat Posts as a reach and audience-research surface and the subscriber
Community as a moderated discussion space. Do not turn Posts into a duplicate
announcement feed or claim that post engagement causes video distribution.
