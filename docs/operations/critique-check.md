# Critique Check

Trigger: `critique check`, `critique-check`, or `run critique check`.

Use this loop to strengthen a content idea before committing production time:

`best-effort pitch -> critical review -> recorded lesson -> improved next pass`

The [twenty-round Shorts lab](../../youtube-series/shorts/pitch-lab/2026-09-05/README.md)
is the worked example. It preserves the original pitches, critiques, decisions,
and lessons. These are editorial judgments, not audience experiments.

## 1. Establish scope and read the rules

- For an open search for the next Short, default to twenty distinct concepts.
  Twenty hooks for the same idea do not satisfy that scope.
- When the user supplies a particular pitch, critique and revise that pitch.
  Do not replace a focused review with twenty unrelated ideas. Make a second
  review pass on the revision and report any remaining weakness.
- Honor an explicit format, topic, count, or stopping condition. Do not confuse
  the next Short with the next long-form episode.
- Read the [short-form playbook](../../youtube-series/production/short-form-playbook.md)
  for Shorts, or the [long-form playbook](../../youtube-series/production/long-form-playbook.md)
  for long-form. Keep their evidence and pacing rules separate.
- Read the [copy playbook](../../youtube-series/production/platform-copy-playbook.md).
  For a `publishing.md` review, use the
  [publishing checklist](../../youtube-series/production/publishing-playbook.md)
  and its P01-P18 audit, critique, and score instead of scoring it as a script.
  For visual plans, also read the
  [visual guidelines](../../youtube-series/production/visual-asset-guidelines.md).
  For Shorts, read the [upload gate](short-upload-gate.md) before planning the edit.
- Consult the [idea ledger](../../youtube-series/content-ideas.md), recent
  scripts, and previous pitch labs to check novelty and prior deferrals.
- When using audience evidence, read [analytics and evidence](analytics-and-evidence.md)
  and the latest relevant report or comment review. Name the evidence used;
  distinguish observations from explanations and creative hypotheses.
- This command does not trigger an engine check, automatic analytics refresh,
  or tweet-data pull. Use existing evidence unless new collection is requested.

## 2. Create a traceable working record

Use a new `youtube-series/shorts/pitch-lab/YYYY-MM-DD/` folder for an open Shorts
search. Add a numeric suffix if that folder already exists. Never overwrite an
earlier run. For a focused review, keep a separate review file beside the pitch.

For a full lab, create an index, an evidence note, numbered round files, and an
append-only learning log under `docs/logs/`. Link these records together. Keep
bookkeeping and individual critiques out of AGENTS.md.

## 3. Write the strongest pitch, then switch to critic

Run these roles sequentially. Separate roles do not imply independent agents
or outside review, and this procedure does not require delegation.

### Writer

Make a genuine best effort. Never write a weak pitch to make the critique easy.
For each Short script, use the required workflow and S01-S20 in the
[short-form checklist](../../youtube-series/production/short-form-playbook.md):
first explain how the draft will attempt every item, then provide the script.
The critic must then audit every item, give a substantive critique, and finish
with the weighted score and decision. This is required on each new or rewritten
Short script, not only when this command is invoked. Keep the checklist and
scoring rules authoritative there rather than maintaining a second rubric here.

For each new or rewritten long-form script, use L01-L16 and the same
plan/script/audit/critique/score workflow in the
[long-form checklist](../../youtube-series/production/long-form-playbook.md).
Use its own weights, mandatory checks, evidence, and ending. Do not apply the
Shorts controversy requirement, immediate post-reveal why-question, or runtime
gate to a long-form lesson. This workflow also applies without this trigger.

Later rounds must name the earlier lesson they apply. Write and review each
round before starting the next; do not generate all pitches and critique later.

### Critic

Challenge the premise as well as the wording. For both script formats, complete the
item-by-item checklist audit before prioritizing the substantive weaknesses.
Other pitch reviews may follow the worked example's five itemized risks, but
never invent faults or pad a review to hit a count. For each issue, explain
the consequence and name a repair, a test, or a reason to reject the idea.

For long form, prioritize the opening promise, immediate useful action,
capability-based sections, essential reasoning, verified code progression,
and completion using L01-L16. The following additional questions focus on
Shorts; use only those relevant to a different format's requested pitch:

- Does a cold viewer understand the appeal on the first frame? Does the hook
  sell the idea before terminology, setup, and qualification consume attention?
- Is the idea interesting enough, or merely a familiar trick with a louder hook?
- Can the demonstration fit the time and screen without prerequisite lessons?
- Is the disagreement substantive? Would revealing the full setup reinforce
  our competence, or expose a misleading comparison or contrived mistake?
- Does the evidence support the exact claim and its proposed explanation?
  Check unchanged data, required outputs, timed costs, and relevant optimization.
- Do we deliver the real payoff and immediately ask why the audience thinks
  it happened, before the adjacent question and next experiment? Does the
  outro preserve discussion while giving viewers a concrete reason to return?
- How much proof and production work remains? Could a simpler candidate
  deliver the same viewer value sooner?

Preserve strong, correct claims and deliberate omissions. Critique must not
turn every objection into another spoken caveat. Mark the decision `advance`,
`rework`, or `hold`, with reasons. For scripts, calculate the editorial score
using the playbook weights and mandatory checks. Never turn that score into
a predicted reach score or final-export approval.

## 4. Record the lesson and apply it immediately

- Append the lesson, its source round, and the next action to the run log.
- Add or refine a reusable editorial check in the relevant playbook before
  the next pitch. If an existing rule covers the issue, cite it instead of
  adding a duplicate. Keep candidate-specific repairs in that candidate's file.
- Label creative judgments as working editorial checks. Do not claim the
  audience validated a rule because it survived an internal critique.
- In the next round, show how the lesson changed the work. Do not merely record
  a criticism and repeat the same mistake under another topic.

## 5. Select, verify, and hand off

- Compare the candidates on opening clarity, payoff, worthwhile disagreement,
  novelty, proof cost, and production readiness. Explain the tradeoffs.
- Return one recommended pitch, not another unranked list. A brief shortlist
  may accompany it. State remaining weaknesses and the next concrete action.
- Verify the requested round count, distinct concepts, critiques, lesson
  traces, file links, and narration formatting. Word counts estimate pacing;
  they cannot establish the exported duration.
- Consolidate overlapping playbook additions after the loop. Preserve the
  original lessons and their mapping in the append-only log and lab index.
- Record what the check did and did not establish. An editorially selected
  pitch still needs technical proof, platform-specific SEO review, and final
  media checks. Do not mark the Short upload gate passed from a script.
- Do not publish, run an unrequested benchmark project, or commit to a release
  schedule merely because the critique check selected an idea.
