## Pass 1: review the original

Historical narration, preserved for comparison. The current recording version
belongs only in [script.md](script.md).

```text
This unused field is slowing your loop.
We only need scores, but look how far apart they sit.
Put the scores together and keep the history separate.
These lookups run twelve times faster here.
What if we need both? That's what I'm testing next.
```

Decision: **rework**. Keep the premise, brief hook, real measurement, and
continuation. The main repairs concern what the viewer sees and understands,
not adding hype or a longer opening.

1. **The first frame labels the surprise without fully exposing it.**
   Eight code lines are within our viewport limit, but reading a struct and
   proving a member is absent from a loop still takes effort. Keep the seven-word
   hook. Use `Never read, still slower?` as the callout, circle `history`, and
   highlight the actual `.score` read. The intended contradiction must survive
   muted viewing before the viewer parses the whole snippet. E1 supports the
   urgency; whether this revised frame succeeds remains a visual test.
2. **The explanation points at distance without clearly connecting the field
   to it.** `Look how far apart they sit` can feel like an instruction to admire
   a diagram. Name the history as the source of the spacing, show the actual
   record layout, and keep the indexed loop anchored while the layout changes.
   E3 establishes the layout and measured win, not a twelvefold cache-miss
   reduction. Do not invent a cache-line animation or force a new architecture
   lesson into the speech.
3. **The edit could look like removing data, while the result adds new labels.**
   A cold viewer must follow a struct, a memory graphic, then `Player objects`
   versus `Split storage`. Preserve the history during the edit and say that no
   data was deleted at the payoff. Use `Before` and `After` on the measured card.
   Keep the same IDs and loop structure visible through the edit; update only
   the actual lookup expression. This applies the existing fair-task and
   prerequisite-burden checks, supported by E3.
4. **The reveal has no progression after the table appears.**
   The original plan shows both numbers, then holds the card for the rest of
   the Short. E1 gives us a reason to test a staged reveal, not a mandate to
   hold the answer back longer. Show the baseline shortly before the new time;
   reveal the new time and ratio with the spoken payoff. Enlarge the result,
   retain readable order/size/optimization context, and continue directed
   annotations and movement. Do not add a countdown or fake running timer.
5. **The outro does not ask the viewer to predict an outcome.**
   `What if we need both?` leaves both the referent and the actual question
   implicit after a benchmark-card cut. Ask whether the split layout would
   still win if the loop read the history too. Point back to the retained data.
   Keep the next-test sentence and immediate cut. E2 supports leaving a real
   tradeoff open; it does not justify assuming either answer.

Lessons recorded before revision: make the unused/read distinction visible;
keep a stable code anchor; show data preservation; stage a real result without
padding; ask for a prediction about a named workload change. All map to existing
playbook rules, so no duplicate rules or bookkeeping belong in AGENTS.md.

## Pass 2: review the revision

The revised narration has 54 whitespace-delimited words, compared with 44 in
the original. The added words identify the memory relationship, unchanged
lookups, retained data, and the proposed follow-up workload. More words are not
the objective. Short 5's rapid delivery is not evidence that every new Short
should match its words per minute.

1. **Opening: advance, with a visual check outstanding.** The seven-word hook
   stays intact. The new callout and two targeted code annotations expose the
   contradiction without adding a preface. The first two seconds still depend
   on readable code and immediate emphasis. Inspect an actual phone-size first
   frame before recording the full take; this review cannot declare it passed.
2. **Explanation: clearer, deliberately incomplete.** The history now explains
   the score spacing, and the same indexed loop anchors both layouts. Cache
   hierarchy and addressing details remain omitted. We are showing a supported
   layout effect, not claiming to have measured every component of the cause.
   Final visual repair: keep this a legible schematic of storage, not a literal
   byte-scale drawing or invented cache-traffic trace.
3. **Payoff: stronger and appropriately scoped.** `Before` and `After` need no
   new storage vocabulary. The new time appears with the ratio, not seconds
   before its narration. The history remains present, and the spoken result
   explicitly preserves the data. Ordered IDs, size, normal optimization, and
   scalar kernels remain visible. That is a meaningful proof burden; it must
   not become an unreadable fine-print footer.
4. **Outro: a real prediction, with a screen-space risk.** Reading the history
   could change the tradeoff, and naming it removes the old ambiguous `both`.
   The question earns discussion without asking for follows or withholding
   the current result. Returning a full diagram beneath a full table would
   overcrowd the frame. Final repair: reserve room for two compact labeled
   lanes while retaining the readable times and workload context.
5. **Novelty and performance remain uncertain.** This still overlaps Short 4's
   broader memory theme. Its distinguishing idea must remain the unread field,
   not a generic lesson about arrays being fast. A revised script cannot prove
   that the topic is more interesting, that the first frame will hold viewers,
   or that this next-test wording improves conversion. Do not add a second
   experiment or inflate the claim to compensate for that uncertainty.

Decision: **advance to a timed rehearsal and first-frame mockup**. The selected
lookup measurement already supports the numerical claim. The proposed
score-plus-history experiment has not been run. No publication, benchmark
rerun, platform SEO approval, or upload-gate pass occurred during this review.

## What changed and what to test

- Kept: topic, seven-word hook, ordinary compiler optimization, indexed lookup,
  real result, deliberate technical omissions, question, and next-test ending.
- Changed: callout, memory explanation, visual continuity, data-preservation
  wording, staged result labels, and the specificity of the outro.
- This is a combined creative revision, not an isolated A/B test of the hook.
  Preserve the original version above rather than rewriting its history.
- Before recording: inspect the first frame silently at phone size; read the
  canonical script aloud; check the result/context and compact outro lanes at
  the same viewing size. If the read finishes early, cut early. All four final
  upload checks remain unverified until the exported video exists.
- After publication, compare Instagram at matched ages: opening retention
  around three/four seconds, retention through the edit and numerical reveal,
  completion, audience comments and thread depth, saves, shares, profile visits,
  and Reel-attributed follows. Use reach as the denominator where available;
  separate creator replies from audience participation. Review whether people
  debate field-access tradeoffs or misunderstand basic test conditions.
- Keep YouTube and TikTok results separate. Do not attribute a distribution
  change to the hook, question, hashtag, or posting time alone.
