# Short 08 — input and set-building comprehension test

Two tiny motion previews, 216×230, 24 fps, opaque and silent. These replace
only the opening and insertion demonstration for review; no seven-scene or
full-resolution batch runs here.

1. 01-input-opening.mp4 — 3 seconds. Original hash code and untouched input
   3,1,3,2,1. Only the first source is outlined. Nothing is already stored.
2. 02-build-the-set.mp4 — 10 seconds. Five attempts in source order. First
   occurrences form separate stored keys; duplicates press the existing key
   and add nothing. Stored counts after each attempt: 1,2,2,3,3.

No buckets, rails, pedestals, ropes, moving query copies, destination highlights
or added labels. Thin source-only contours follow the rounded clay silhouette.
Input remains intact throughout. Stored keys are staggered rather than sorted.
This is a logical set-membership demonstration, not hash-function anatomy or
measured memory traffic. Native clay, lighting, code and composition are reused.

build.py and contour.py reproduce the scene; audit.py checks input preservation,
stored-key counts, one highlight, text bounds and every visible value-box pair.
render_preview.py renders directly at 10% and fully decodes both MP4s.
No image-inspection loop or native render is part of this test.
