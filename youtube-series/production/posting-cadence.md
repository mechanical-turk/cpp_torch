# Standing Posting Cadence

This is the recurring weekly routine across all distribution channels. It
operationalizes the principles already stated in `AGENTS.md` (release ledger,
distribution lessons, video/Short scripting rules) into a concrete weekly
grid. Update this file when the cadence itself changes; log actual events in
`docs/distribution-timeline.md` as always.

Standing priority, restated from `AGENTS.md`: protect at least 70% of
available time for scripting, implementation, recording, and editing.
Distribution never expands to fill available time just because a slot exists.

## Per-category rules

**Main playlist (long-form).** Monday/Wednesday/Saturday, 11:00 AM ET, per the
existing cadence. A slot with nothing ready to publish is simply skipped, not
filled with a lesser release.

**Shorts across YouTube, X, Instagram, TikTok.** Target two independently
produced Shorts per week (Tuesday and Friday), each uploaded natively to all
four platforms rather than cross-posted or backlinked. Two per week is
deliberate: enough to keep accumulating independent retention data points
against the progressive-disclosure hypothesis, without displacing long-form
production time. Draw from the 64-idea backlog in
`youtube-series/shorts/episodes-01-04-ideas.md`.

**TikTok.** Joined the rotation as of Short 2 (2026-08-18): the 9:16 master's
right-edge/bottom safe-area issue that previously clipped content under
TikTok's UI is resolved, so the same universal export now serves YouTube
Shorts, Instagram, and TikTok without a platform-specific re-crop. Treat
Short 2 as TikTok's first data point, not a validated format — compare its
checkpoints against the equivalent X and Instagram numbers before drawing
conclusions from raw view counts alone.

**Native tweets (non-announcement).** One per week, Tuesday, distinct from
both episode announcements and personal/process posts. This is a single
technical insight, visualization, or code snippet — the kind of thing already
tested once (the tensor-storage visualization on Aug 16). Skip the week if
nothing genuine exists; do not manufacture one to fill the slot.

**Native LinkedIn posts (non-announcement).** One per week, Thursday.
LinkedIn's audience rewards lower frequency and more substance than X: either
a native Short repost or a short technical write-up, never both in the same
week. This is also LinkedIn's designated slot for testing native-video
completion against the X native upload, per the existing Short-1 LinkedIn
test.

**Episode announcements (X and LinkedIn).** X announces the same day as
release, approximately one hour after publication, always with the standard
playlist-and-GitHub navigation reply beneath it — never as an expanding
episode-to-episode reply chain. LinkedIn announces the next weekday morning
(9:00-10:30 AM ET), at least one full day after the X announcement, so the two
platforms don't compete for the same attention window. A Sunday release
still gets its LinkedIn announcement the next weekday morning (Monday).

**Personal/process tweets.** One, occasionally two, on most active days.
Never manufactured to hit a quota. No link or promotional call to action
unless the post genuinely requires it. Rotate across: the emotional reality of
working alone, unexpected things learned rebuilding the machinery, concise
technical opinions, honest mistakes and corrections, and understated
production milestones.

**Relevant X replies.** Check active conversations from accounts and
communities that overlap with C++, machine learning, systems, and current
projects. Reply only when there is a concrete contribution: an informed view,
a useful example, original work, or a real question. This is an active
distribution surface, not a daily quota. Track it separately because the host
conversation supplies reach that an original post does not.

**Reddit.** Treat Reddit as a primary discovery and conversion channel. Every
week must contain a Reddit review and a recorded post-or-defer decision. Sunday
from 12:00 to 2:00 PM ET is the default publication window because the first
r/learnmachinelearning milestone post succeeded there, but timing remains an
experiment rather than a universal rule. Prepare the post during the week,
recheck the live subreddit rules before submission, remain available for the
first two hours, and capture 24-hour, 48-hour, 72-hour, and seven-day results.
Do not post a generic episode announcement. Lead with a concrete project
milestone, useful technical evidence, and one question the community can
answer. Rotate communities only when the work genuinely fits them, and never
paste the same body into several subreddits.

## Explicitly out of this grid

- **Hacker News** remains milestone-gated. r/MachineLearning also remains
  limited to placements allowed by its current rules. Reddit itself is now in
  the weekly grid, while each individual subreddit and submission still needs
  a fresh relevance and rules check.
- **Analytics checkpoints** (24h, 72h, 7-day) are triggered by publication
  events, not calendar days — see `AGENTS.md`'s YouTube/Instagram operations
  sections for the standing rules on when to refresh.
